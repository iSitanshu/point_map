# T-016 — PWA: installable, offline tiles

**Status:** done · **Priority:** P0 · **Estimate:** M · **Governed by:** ADR-0003

## Why this jumped from "later" to P0

The user said it plainly: *"I want to use this on my mobile too, so I need not open my laptop each time."*

That reclassified the whole task. A localhost-only app is a laptop app, and the moments this tool exists for — standing outside a PG, a broker's message at 11pm — happen on a phone. Shipped together with a GitHub Pages deployment, because being installable is useless without being reachable.

The original reasoning still stands on its own:

Journey (b) from the brainstorm: standing outside a PG with one bar of signal. Data already works offline (localStorage), but the *app shell* and the *map tiles* do not — so the page may not load at all, and if it does the map is blank. That is the moment the notes get written, so it is the moment the app most needs to work.

Also the prerequisite for real background reminders (T-012).

## Acceptance criteria

- [x] `manifest.json` with icons; installable to a phone home screen
- [x] Service worker caching the app shell (HTML/CSS/JS) cache-first
- [x] Map tiles cached stale-while-revalidate, capped at ~50 MB with LRU eviction
- [x] Visible offline indicator; no spinner ever blocks a write
- [x] Update prompt when a new version is deployed — never a silently stale shell
- [x] Works as a plain website with the service worker unregistered

## What shipped

- `manifest.webmanifest` — standalone display, theme colours, three icons
- `app/icons/*` generated by `tools/make-icons.py`, a pure-stdlib PNG encoder: no Pillow, no build step, re-runnable
- `sw.js` — three caches with three policies: app shell stale-while-revalidate, OSM tiles cache-first capped at 300, Leaflet cache-first. Google Maps is explicitly **not** cached; it is session-bound and caching it would break it.
- Update prompt — a new version announces itself and waits for a Reload tap rather than swapping underneath the user
- An **⤓ Install** button in the top bar (Chrome/Android), an offline chip, and iOS instructions in the docs since Safari has no install API
- Safe-area insets so the top bar clears the notch in standalone mode
- `@media (pointer: coarse)` — bigger icon buttons, stars and checkboxes, and 16px inputs so iOS stops zooming on focus
- `.github/workflows/pages.yml` — tests then deploy on every push to main

## Notes

Service workers are the one place where "no build step" (ADR-0003) genuinely hurts: no bundler means no content hashing, so the asset list is maintained by hand in `SHELL` and `VERSION` has to be bumped when app files change. Accepted, and written down at the top of `sw.js` so the next person knows.

`cache.addAll()` was deliberately avoided — it fails the entire install if any single file 404s, which would be a silent and permanent breakage. Each file is added independently and a miss is logged.

Tile caching must respect OSM's tile usage policy — cap the cache, never bulk-prefetch a region.

A stale service worker serving old JS is the classic failure. Version the cache name and `skipWaiting` only after the user accepts the update prompt.
